# Findings

普通 Handoff 对用户提示和助手解释做了压缩，不能当完整需求。现有 evidence.selection_bundle 能导出修订绑定的完整所选消息，摘要有独立 representation。复用此接口，不新增解析器或模型执行平台。

导出是选段，不保证覆盖全部需求或后续修订。原生数据库及超过有界源快照的消息导出限制继续显式披露。一次包容不下时分批核对，不用摘要冒充原文。

独立复核发现搜索前三命中可能全为助手，无法选到后续用户原文。已新增修订绑定的用户消息分页入口，按完整会话绝对序号定位，排除环境上下文；对超出来源快照的需求不建议改用摘要。

合成接手验收正确处理后续修订并发现两处当前代码缺陷，详见 acceptance.md。工作流复用知识页现有的“历史声明与当前验证分开”规则，无新增通用知识规则。

## CBC / AGY / mcode / ZCode 正式交接

- CBC 原本已有文件证据路径；新增四来源同 ID 的混合包验证，避免只把名字加进界面。
- AGY 的派生索引无文件签名，ZCode 的显示顺序由 sequence 决定：使用各自公开消息快照并保留阅读器绝对编号；thinking 不导出也不重编号。旧 partial/legacy AGY 仍可浏览有限审计，不提供完整需求交接。
- mcode 的权威输入是 messages.jsonl + 固定 manifest.json。原索引使用九元复合签名，普通文件证据只比较五元，导致刚刷新仍报来源改变；统一签名并绑定两文件 bytes。原 audit 未支持 mcode 时曾回落到 Codex，现复用公开块解析生成真实审计。parser v2 让旧 mcode 索引重建。
- 不执行或安装 CLI；用户已明确选择只接通四来源完整交接。普通来源读取与旧原生数据库 SHM 行为边界见 docs/local-cli-sources.md。
