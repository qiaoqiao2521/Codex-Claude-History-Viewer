# 实现模型 → 验收模型交接

## 目标

用户希望一般/低价模型完成主要实现，再通过 TraceMesh 精准交接需求，让高级模型对照当前代码验收、提出必要优化。README 介绍这一用途。

## 范围与验收

- [x] 复用所选完整消息导出，增加验收交接包；至少一条用户原文，摘要不可替代。
- [x] 网页提供明确入口、用途选择、预览/复制/下载和缺失需求提示；切换用途后旧响应失效。
- [x] 接手提示词区分原需求、后续修订、助手声明与当前代码；逐项输出状态和依据。
- [x] 更新 README、PROJECT 和简短使用文档；测试和合成浏览器闭环通过。

保留本地处理、修订绑定、脱敏、5 条/8000 字上限和来源不支持披露。不自动调模型、不读历史 cwd 下的代码、不执行或自动判完成；真实验收由用户选定的模型在指定仓库中进行。保留已有未提交素材功能。

## 采用经验

Wiki/自动化开发范式与智能体协作「按当前任务选择验收依据」：历史声称完成和当前交付验证分开；本轮验证交接工具，不冒充高级模型已验收真实项目。

## 四来源完整交接（本轮追加）

用户明确要求 CBC、AGY、mcode、ZCode 正式接入，并确认本轮只做来源交接，不启动 CLI。

- [x] 复用 CBC 文件记录；AGY/ZCode 绑定原生公开消息快照；mcode 绑定 messages 与 manifest。
- [x] mcode 网页自动发现、设置展示、需求分页与完整消息导出。
- [x] 四来源检索 → 原始需求/修订 → 预览/下载验收包；超限、过期、非公开内容拒绝。
- [x] 合成来源 HTTP、浏览器与回归验证；更新来源能力说明。
