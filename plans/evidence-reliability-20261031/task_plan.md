# 历史证据可靠性修复

## 目标与依据

用户提供针对 `17b4786` 的八组缺陷审查；当前本机 HEAD 相同。核对原症状后修复所有仍存在的问题，优先保护原记录与外发内容。只用临时合成来源测试，不移动真实历史、不发起模型请求、不替换安装或发布发行版。

## 范围

1. 归档／删除备份不覆盖已有记录，失败不误报成功。
2. API Host 与写请求来源检查统一；GET 重建索引改为受保护 POST。
3. 旧 handoff 复用脱敏，包括计划文本与渲染出口。
4. Web 共用解析版本；普通索引保留同 ID 不同录制。
5. 会话搜索按 source_revision 一致读取。
6. 长会话绝对消息编号、全文展开、搜索清除与失效处理。

## 验收

用实际 Indexer、Handler 与现有前端测试设施覆盖上述复现；独立检查跨入口行为，再运行受影响的 Python／JavaScript 回归。记录源码修复、合成运行与实际浏览器验收的边界。报告中的容量产品改进与 WAL 只读语义另列，不顺带改容量或源库策略。

## 连续性

owner：根 Codex；前端由内置子 Agent 独立处理，后端与共享核心串行整合。保留原有未跟踪计划、锁与用户材料。采用 MEMORY 对 TraceMesh 的来源只读、覆盖披露和验收分层约定；当前事实以本仓代码及本轮测试为准。
