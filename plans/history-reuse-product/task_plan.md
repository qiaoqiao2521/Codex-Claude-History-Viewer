# History Viewer：找回、理解与复用历史

Status: **engineering_complete / U1 cancelled by user (2026-10-01)**。范围版本 **HV-reuse-linux-v1**；实施 **5/5**，工程验收完成。当前主线为 Agent 检索、证据定位与验收交接；独立人类试用不再是待办或发布门槛。

## Goal

让 Linux 用户从一个问题、项目或文件进入历史，找到具体证据，理解工作停在哪里，并选择有依据的上下文继续工作。沿用已发布 v1.2.0 的只读 reader、索引、审计、交接与原生续接命令。

旧 [Linux 独立交付](../bounded-delivery/task_plan.md) 保持 5/5 complete；本计划是新一轮产品建议，不能覆盖旧验收，也不能把旧测试计为新功能验收。

## Background and scope

- 当前基线 `main` / `a58df9a817f93ba3ddc84ca14193dd8ad380e495`。已具有来源修订、稳定分页、消息内搜索、文件过滤、六栏目概览、handoff 导出、resume command 和 Linux 启动脚本。
- 统一证据搜索是首要方向；除此以外，本计划建议首次使用与来源诊断、项目时间线、文件改动追溯、选择性证据交接四项增量。

## E0 — 固定任务基线（实施前第一步）

复用 `demo/`、现有生命周期 fixtures 与历史 M3 任务单，制作最小的可重复任务集：至少 3 项目、2 来源、20 个有答案的固定检索题（每题标注目标 source/store/session/message），另设至少 4 个无匹配负例及独立契约用例；覆盖中文、报错短语、文件路径、同名项目、同名会话、无匹配、一个来源失败以及索引变化。材料只用合成/明确脱敏数据。

只对 20 个有答案题计算前 5 条结果命中目标证据的比例（Hit@5），负例、来源失败、索引变化和分页契约另计且逐项正确；记录找到消息的操作次数，以及下述五个端到端任务的结果；人工耗时与 Agent 自动测试分别记录。先保存基线和题目，再改变排序。来源适配支持情况与测试覆盖单独列矩阵，不能用 JSONL 成绩代替 SQLite 来源成绩。

五个任务：启动并理解来源状态；跨来源找一次修复；还原项目最近工作；追溯指定文件；选择证据导出交接。任何模糊查询未找到，保留原题而非事后改成容易命中的关键词。

## HV-R1 — 统一证据搜索

- 首页提供全部已配置来源的搜索入口，支持项目/来源/日期缩小范围；保留原会话浏览。
- 返回匹配原因、命中片段、项目、来源和时间；默认按可解释的词项匹配相关性排序，时间为辅助。中文、路径和精确错误文本不能被分词改造破坏。
- 点击结果定位消息并保留搜索上下文；零结果、部分来源失败、修订失效、截断分别可见。
- 跨来源身份使用 source/store/session 组合；分页绑定来源修订集合，任何参与来源变化后显式失效，不混入新旧页。
- 复用既有消息内检索/定位，先比较当前查询与标准库可用方案；本轮不预设向量库或引入新引擎。

验收：E0 的 20 个正例至少 16 个在前 5 条找到目标证据（Hit@5 ≥80%），4 个无匹配题不得制造匹配（建议目标，执行前冻结，不因失败删题）；前 5 条均能跳到正确来源/会话/消息；同 ID 不同来源不碰撞；失败来源不显示成成功空集；跨页无重复/遗漏或明确失效。跨来源性能数据固定为共 10k 会话（Codex/Claude 各 5k、每会话 20 消息、约 16KiB），复用原生成方法并在 E0 固定种子、数据摘要和环境；不声称适用于原生数据库。索引建好后预热 5 次、固定查询序列测 100 次，从本地 HTTP 请求发出至完整首屏 JSON 接收完成计时，按 nearest-rank 取 p95，目标 ≤1s；首次新服务进程查询单列，不称 OS 冷缓存。浏览器绘制耗时单列；原生 DB 先另记功能/实测能力，不套用该成绩。保留旧单源门槛。结果最多 20 条/页、每条最多 3 段摘录且每段 240 字符；内部扫描须有有界策略，截断必须显示。

入口：`history_core/{reader,service,sources}.py`、`app.py` 搜索路由、`static/{workspace,app}.js`；不要建立第二套 parser。

## HV-R2 — Linux 首次使用与来源诊断

- 首次打开能选择合成演示或查看已发现来源；真实来源路径、会话计数和扫描范围可理解。手动纠正路径的最小形式可为可复制的启动参数，不强制增加配置系统。
- 区分不存在、不可读、格式不支持、正在索引、最近成功、失败后旧缓存以及 freshness unknown；只有实测刷新成功才显示刷新时间。
- 错误提供对应下一步，例如检查路径/权限、显式刷新。复用现有 health、版本接口、启动/桌面脚本及安装验收工具。
- 改善首页信息层级：主要动作是找历史和回到项目；详细技术状态展开可看，避免每张卡重复同一段未知状态说明。
- 诊断导出仅显式操作；默认包含版本、错误代码及脱敏统计，省略转录、用户名、绝对路径和密钥；预览后保存到本地，不自动发送。

验收：干净 Linux HOME 中，演示、零来源、一个可用来源、路径错误、权限错误、来源变更及服务失联均有正确状态和可执行提示；demo 不改真实缓存；诊断含植入的模拟敏感信息时输出不泄露；仅键盘可完成主要路径，420/480px 无横向溢出；重新用当前安装工具验证 clean install。截断尾行与完全损坏日志分别验证，不能把可恢复尾行一律报成不可用。Windows/WSL 不作为本轮门槛。

## HV-R3 — 项目时间线

- 首页按项目展示跨来源会话，进入项目后按时间查看目标、变更、验证、失败和后续记录；活跃项目的多条会话归入同一项目入口。
- 默认按完整工作目录识别项目，缺 cwd 明示未绑定；同 basename 不合并，worktree/别名仅在身份有证据或用户显式关联后处理。来源去重不依赖标题相似度。
- 给出最近工作和可核对的下一步，旧失败与后续成功分别保留来源；没有明确对应证据就不能自动判断阻塞解除或某个决定已生效。
- 当前 SpecMesh 文件按既有有界扫描显式读取，与历史会话标明不同观察时间；不复制为第二份项目决定数据库。

验收：一个项目多来源、多会话可完整分页；两个同名不同路径项目保持分开；未绑定会话可访问；后续无关成功不能覆盖早期失败；每条历史变更/验证可回到对应原文；分页、读取上限和不完整范围可见。项目概览不默认展开所有长日志。

## HV-R4 — 按文件追溯改动

- 从已记录的文件路径进入项目内的跨来源、跨会话时间线：谁在何时对它做过什么、工具结果如何、附近有哪些测试记录。
- 复用已有 `file_path` 精确过滤、审计 change/evidence 和消息定位；已有单来源跨会话文件过滤不重复实现；新增项目隔离下的跨来源时间线、消息级改动证据和邻接验证。
- 有结构化 patch 才展示差异；只有路径或命令时展示对应证据并注明 diff unavailable。工具调用、写入成功、历史验证和当前文件状态分别呈现。
- 原始路径、项目和来源保留；重命名只在显式 rename 证据存在时关联。当前文件不存在不妨碍查看历史；不自动读取当前文件或执行 Git/测试来补证据。

验收：`a.py` 不混入 `a_backup.py`，不同项目同名文件隔离；一个文件横跨多个会话可分页定位；页内候选经精确过滤后不提前宣称结束；失败 patch 不标成功修改；未知重命名和无 diff 明示；只读效果和有界读取保持。

## HV-R5 — 选择性证据交接

- 先统一 Web `/audit` 导出与机器 `service.handoff` 的有界来源快照/provenance 路径；沿用现有 schema 兼容字段，未知修订仍显式 unknown，不能由 Web 补猜。先完成这一子项并验证，再增加跨会话选择。
- 从检索/项目/文件视图勾选证据，预览后复制或下载 Markdown/JSON；复用已有 handoff 结构和渲染，保留原单会话导出。
- 首版最多 5 个证据片段、正文合计 8000 字符；预算针对导出结果，不允许先全量读取再截断。超限提示选取，不能悄悄丢尾部。
- 每段包含来源定位、内容修订或明确 unknown、观察时间；推断和用户补充说明单独标记。跨会话只集合证据，不自动产生已确认决定。
- 默认只带选中片段及必要上下文；已有 secret-pattern 检测能复用则复用，否则最小规则遮盖常见密钥/令牌并显示遮盖提示。规则不是完全匿名化保证，保留导出预览。
- 文件变更后的旧引用显式 stale，禁止悄悄换成新原文。已有 resume command 可复制；Viewer 不自动执行 Agent，也不写回 SpecMesh。

验收：同一受支持会话在 Web/机器接口的来源身份、修订和证据绑定一致，未知/不支持能力保持一致；两来源、多会话选中集合准确；未选内容不混入；模拟密钥在预览/Markdown/JSON均按同一规则处理且源文件不变；预算、缺失源、修订变化均可见；带 shell/HTML 文本的历史内容仅作为数据；关闭再打开不声称已有接收者采纳或执行。
