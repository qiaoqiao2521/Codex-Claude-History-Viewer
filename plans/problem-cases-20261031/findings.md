# Findings

- 用户目标超出原历史检索 5/5 范围；本轮首版不重标旧计划为未完成，也不声称整个知识产品完成。
- 既有三路归因文档位于 `plans/review-feedback-attribution`，起源提交 `1a4ee95d55fbc4cba3c6e9af4b6d1e47770fbe02`。公开记录表明实际材料限制与产品能力须分开，原始私有输出未读，不伪造原对话证据。
- `indexed_materials` 绑定 index_revision，`selection_bundle` 绑定 content/context_revision，两者不能互换；案例保存不强制重验历史，也不从旧指令自动恢复执行。
- 现有材料 writer 内容版本文件名与人工改稿冲突保护只适合快照；本轮沿用脱敏而不扩展内容锁。
- 搜索按标题、问题、标签、解释文本，返回完整案例解释入口；不使用 value_score，不按出现更晚自动认定替代。
- 独立复核发现四项具体边界并已修复：不支持目录 fd 的平台使用同目录原子替换；结构化备注的秘密键和值沿用共享脱敏词汇；NaN/Infinity 不作为合法 JSON 流出；可选对象字段不会使整个网页列表清空。新增回归先复现对应失败，再验证修复。平台分支为模拟 API 能力，未做 Windows 实机验收。
- 未参与原任务的 Agent 从 CLI 帮助发现 cases，检索“冻结”和“来源”，只展开三路归因案例；在新的受限材料评审场景中先核派遣材料与检索权限，未重复采纳强制全库扫描或隐藏不支持来源。这是一次受控迁移判断，未实际复现新场景的产品故障，也不证明方法普遍有效。
